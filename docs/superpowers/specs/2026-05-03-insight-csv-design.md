# Insight.csv — Design Spec

**Date:** 2026-05-03
**Status:** Approved (ready for implementation plan)
**Scope:** Local-only, dev-only React web app. Single user, single session.

## 1. Problem

Build an AI-powered data analysis web app. The user uploads a CSV, sees a preview, types a natural-language question, and receives both a plain-English insight and one or more charts — all generated by Claude. No coding, no setup beyond `npm run dev`.

## 2. Stack

| Concern | Choice |
|---|---|
| Build tool | Vite |
| UI framework | React 18 |
| Language | TypeScript |
| Styling | Tailwind CSS |
| Components | shadcn/ui (copied into `src/components/ui/`) |
| Charts | Recharts |
| CSV parsing | PapaParse |
| LLM | Anthropic SDK (`@anthropic-ai/sdk`) — Claude Sonnet 4.6 |

## 3. Architecture

Single dev process. The Vite dev server hosts a tiny middleware plugin that proxies one route to Anthropic, injecting the API key from `.env` at request time. The browser bundle never sees the key.

```
Browser (React)        Vite dev server               Anthropic
  │                          │                           │
  ├── POST /api/anthropic ─▶ │                           │
  │   { question, columns,   │   adds                    │
  │     rows }               │   x-api-key header        │
  │                          ├── POST /v1/messages ────▶│
  │                          │                           │
  │                          │◀───── tool_use response ──┤
  │◀── 200 { insight,        │                           │
  │     charts: [...] } ─────┤                           │
```

`npm run dev` is the only command needed. No separate Node process.

## 4. Data flow (single ask)

1. User drops a CSV onto `UploadCard` → PapaParse → `Dataset = { columns: string[], rows: Record<string, string|number>[] }`.
2. `PreviewCard` renders the first 20 rows.
3. User types a question in `AskCard`, clicks Ask.
4. `lib/anthropic.ts` POSTs `{ question, columns, rows }` to `/api/anthropic`.
5. Vite plugin (`server/vite-anthropic-proxy.ts`) builds an Anthropic `messages` request:
   - Model: `claude-sonnet-4-6`
   - System prompt: "You are a data analyst. Use the `present_analysis` tool to return your answer."
   - User content: the question and the dataset (JSON-stringified, columns + rows).
   - Tools: a single `present_analysis` tool (schema below).
   - `tool_choice: { type: "tool", name: "present_analysis" }` — forces structured output.
6. Plugin extracts `tool_use.input` from the response, returns it as JSON to the browser.
7. `App.tsx` updates state; `InsightCard` and `ChartsGrid` re-render.

## 5. Structured output contract

Anthropic tool use is used to guarantee shape. One tool:

```ts
// Tool: present_analysis
{
  insight: string,            // plain English; 1–4 short paragraphs
  charts: Array<{
    type: "bar" | "line" | "pie",
    title: string,
    xLabel?: string,
    yLabel?: string,
    data:
      | Array<{ label: string; value: number }>     // bar, pie
      | Array<{ x: string | number; y: number }>    // line
  }>                          // length 1–4
}
```

Browser-side `Result` type matches this exactly. No free-text JSON parsing — only the tool input is read.

## 9. Error handling

| Case | Behavior |
|---|---|
| CSV parse error (PapaParse `errors[]` non-empty) | Red banner inside `UploadCard`. Reset state. |
| File too large (>2MB **or** >10,000 rows) | Warning modal: "Large file — sending to Claude may be slow/expensive. Continue?" Confirm or cancel. |
| Network failure to `/api/anthropic` | Toast: "Couldn't reach the server." Previous result preserved. |
| Anthropic 4xx/5xx | Toast surfaces status + Anthropic error message. Previous result preserved. |
| No tool call in response, or invalid tool args | Toast: "Couldn't parse a chart from this answer — try rephrasing." |

No retry logic in v1. No client-side rate limiting.

## 10. Testing

- **Vitest** unit tests for `lib/csv.ts` — happy path, empty file, mixed types, missing headers, mismatched row widths.
- **Vitest** unit test for the proxy plugin's request shaping — given `(question, dataset)`, asserts the body it would send to Anthropic includes the right system prompt, tool definition, and `tool_choice`.
- No component test suite. UI is verified by running the dev server and exercising the flow with a sample CSV.
- Sample CSV checked into `samples/` for manual testing.

## 11. Out of scope (v1)

- Multi-question history / conversation memory (each new ask replaces previous result).
- Saving sessions / browser persistence.
- Streaming responses (one-shot `messages` call).
- Auth, deployment, multi-user.
- Editing, filtering, or transforming the CSV in-app.
- Chart types beyond bar / line / pie.
- Export / share results.
